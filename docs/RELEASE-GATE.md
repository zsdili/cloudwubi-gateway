# 云五笔 · 每轮发布前强制环节（自我纠查五步，写死）

**发布铁律（用户 2026-09-16 再次强调）：每一次计划里必须有自我纠查、自我修正、自我优化、自我反思、自我提升环节，至少 50 次以上各种情况反复测试评估查验，全绿才发布。**

## 五步强制流程（每轮必做，缺一不可）
1. **自我纠查**：逐条核对用户历史反馈清单（docs/BUG-LEDGER.md 16 项 + 本轮新反馈），列出"疑似未做/未到位"项，用真实接口/真实环境核验，不凭代码印象
2. **自我修正**：查出的缺口立即修（代码/数据/配置），修完跑回归（已有关用例 + 新用例）
3. **自我优化**：对算法/语料做增量改进（排序权重/命中率/覆盖度），每次改进后重跑全量用例
4. **自我反思**：复盘本轮出现的问题根因（如"只查末1-4字导致整句不命中"），写入 BUG-LEDGER 根因列，防复发
5. **自我提升**：把新增用例并入 tests/ 固化（cloud_api_test.py 等），下轮回归直接复用，用例只增不减

## 判定标准（全绿定义）
- 整句联想：context 返回首候选含预期词（SUCCESSION/ASSOC_LINK 命中）
- 边界：空/非中文返回空数组且 HTTP 200（不联想是正确行为，不报错）
- 翻译：词组命中返回词典译文；数字/英文/空返回空 en（正确不翻）；无 HTTP/JSON 异常
- 任何 HTTP 非 200、JSON 解析失败、5xx → 红，必须修复后重测全绿
